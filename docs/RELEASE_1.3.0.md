# Jauria 1.3.0 — continuidad y configuración

Entrega local para macOS Apple Silicon: `Jauria-1.3.0-entrega-local.dmg` y la app correspondiente en `jauria-github-preparation/recovery-settings`. La instalación sigue siendo local, sin firma Developer ID ni notarización; no publica binarios en GitHub.

El tablero ofrece un acceso directo a la conversación principal y reutiliza una continuación que ya esté viva. Se corrige el refresco que podía ocultar la acción de reanudación después de terminar una sesión. Las fases priorizan la sesión de su último checkpoint. El último tablero se recuerda por perfil sin iniciar procesos.

Configuración reúne permisos Pulso, políticas recordadas y revocación, apariencia, límite de sesiones y avisos nativos. Centralizar la interfaz no amplía autoridad: los permisos siguen sujetos a proyecto, proveedor y carpeta, con recordar desmarcado inicialmente. Los permisos nativos de Claude Code y Codex siguen a cargo de sus CLI.

El ajuste local `Jauria-1.3.0-ux-fixes.app` aclara la recuperación: abrir una sesión viva y reanudar una conversación cerrada tienen etiquetas distintas. En el detalle del proyecto aparece una sola acción para la conversación activa y los historiales con el mismo título se distinguen por identificador. Desde una fase se conserva la acción de reanudar cada conversación histórica vinculada. Configuración explica el alcance del acceso y el paso de copiar el comando a la sesión elegida. Cuando ninguna sesión necesita atención, lo indica y desactiva el acceso correspondiente. La compilación y las 157 comprobaciones afectadas aprobaron; la revisión nativa de este paquete ajustado sigue pendiente porque Computer Use rechazó abrirlo, según [la validación](PULSO_VALIDATION_1.3.0.md).

La entrega `Jauria-1.3.0-entrega-local.app` exige elegir la sesión antes de conceder acceso y deja sin seleccionar el alcance de crear proyectos propios. Mantiene el proyecto como contexto al abrir Configuración. La ventana fija el encabezado y Guardar mientras se desplaza el contenido; muestra los cambios de apariencia o límite pendientes de guardar y aclara que cerrar conserva el borrador. Un comando de permiso ya concedido sigue visible si la conexión se interrumpe; al volver, la interfaz pide comprobar la sesión. Pulso conserva el foco y las secciones abiertas al actualizar un detalle, evita reconstruirlo cuando sus datos no cambiaron y presenta una sola acción para la sesión elegida. Se quitó el botón de actualización redundante del tablero; los errores conservan **Reintentar consulta**. Los mensajes de fallo de reanudación ya no muestran detalles crudos del runner. La revisión aplicó a la app los criterios pertinentes de [Taste Skill](https://www.tasteskill.dev/) y las decisiones de navegación y estado explícito de Herdr, sin cambiar la identidad visual.

La compilación release y las suites afectadas aprobaron: Configuración y permisos 54/54, Pulso 129/129 y shell integrada 12/12 en sus navegadores configurados. Computer Use comprobó visualmente Configuración, avisos, foco, navegación y scroll del terminal en un paquete intermedio con el perfil predeterminado. El intento posterior de inspeccionar la ventana con el perfil indicado devolvió `cgWindowNotFound`; la recuperación exacta con las dos plazas ocupadas no quedó revalidada nativamente en esta entrega, aunque sí pasó la prueba integrada sintética. El runner existente conservó su proceso. Consulta [la validación](PULSO_VALIDATION_1.3.0.md) para el alcance preciso.

Se mantienen las decisiones de [la revisión de Herdr](HERDR_REVIEW.md): navegación directa, separación de vista y runtime y señales explícitas de estado. Sin mods JavaScript, SSH remoto ni reanudación automática.

Consulta [el flujo de recuperación](PULSO.md#recuperar-el-trabajo) y [la instalación](INSTALLATION.md). Codex conserva continuidad por historial/contexto; la reanudación nativa de Codex no está incluida. La identidad exacta de Claude no garantiza que el proveedor conserve su historial.

## Entrega local de terminal y MCP

`Jauria-1.3.0-terminal-mcp-local.app` permite iniciar el plan desde una conversación: en **Configuración → Permisos de agentes** se elige una sesión y su alcance, y **Copiar instrucciones para el agente** prepara el comando y la indicación de crear un proyecto o trabajar en el proyecto elegido. La terminal puede crear el proyecto y sus fases sin escribir JSON a mano. El flujo conserva el permiso por sesión y las revisiones e identificadores de reintento del servicio Pulso.

El runner nuevo incluye un servidor MCP local por `stdio` con ocho herramientas de proyectos, fases y checkpoints. Usa el mismo permiso acotado; su configuración es opcional y se aplica a sesiones nuevas. [Pulso](PULSO.md#permitir-que-los-agentes-registren-planes) contiene los pasos de conexión. La entrega no altera la configuración de Claude Code o Codex ni reemplaza el runner 1.2.0 que mantiene las sesiones activas. La CLI copiada sí funciona con ese runner; el MCP requiere abrir sesiones con el runner 1.3.0 del nuevo paquete.

La prueba end to end con un perfil desechable ejecutó el comando copiable en `zsh`, creó proyecto y fase mediante el binario real, y después verificó MCP por `stdio`: creación, reintento sin duplicados, reducción de alcance y revocación. También se probó el enlace con el SDK oficial MCP de JavaScript y la interfaz de permisos en Chromium y WebKit. Consulta [los resultados](PULSO_VALIDATION_1.3.0.md#terminal-y-mcp-local). No hubo push ni instalación sobre las sesiones del usuario.

## Corrección local del cambio entre sesiones

`Jauria-1.3.0-session-switch-local.app` conserva los botones de la lista lateral durante las consultas periódicas al runner. Antes, el refresco podía reemplazar el botón entre presionar y soltar el ratón y perder el clic. La fila actualiza nombre, estado y avisos sin desmontarse; la lista solo cambia de estructura cuando cambian las sesiones visibles o el filtro. Se comprobaron el cambio desde la lista, el selector de panel y la vista dividida sin enviar entrada a los procesos. La app en ejecución no se reemplazó ni se cerró; este paquete se entrega aparte para abrirlo cuando convenga.

La revisión nativa del paquete corregido usó dos fixtures en un perfil temporal y confirmó el enfoque de cada sesión en uno y dos paneles. Al terminar se detuvieron únicamente los procesos sintéticos. La app y los runners del usuario continuaron activos.

## Fluidez de terminales

El mismo paquete local `Jauria-1.3.0-session-switch-local.app` y su DMG incorporan ahora una corrección del sondeo de terminales. La salida de la sesión enfocada ya no espera una respuesta lenta de otra sesión. Las terminales secundarias se consultan por separado, con un ritmo limitado, y una sesión que pasa al primer plano recibe una consulta nueva. Una respuesta anterior no puede volver a escribir salida duplicada tras el cambio o la reconexión.

La prueba integrada con la interfaz real de xterm y un bridge nativo simulado detuvo una consulta de la sesión secundaria: el eco de la principal y después el de la sesión seleccionada aparecieron en menos de 250 ms tanto en Chromium como en WebKit. También comprobó una reconexión y que la respuesta atrasada no duplicara caracteres. Computer Use confirmó el eco y el cambio entre dos terminales sintéticas en el bundle macOS, con un perfil privado. El tiempo de una captura de Computer Use incluye la propia automatización; no es una medida pura de latencia visual. Los procesos y permisos reales del usuario no se modificaron. Consulta [la validación](PULSO_VALIDATION_1.3.0.md#latencia-de-terminales).
